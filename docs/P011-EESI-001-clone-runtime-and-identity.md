# P-011-EESI-001 — Clone Runtime, Identity, Consent, and Evolution Controls

**Canonical source:** `lippytm/Prompt-11-` — P-011-EESI-001  
**Role of this repository:** authorized clone identity and runtime boundary  
**Human owner and final approver:** Charles Earl Lipshay

## Identity separation

- **Charles Earl Lipshay** — real person, legal owner, source of consent, final approver.
- **lippytm** — creator call sign and repository identity.
- **lippytm.AI** — business, publishing, education, and systems interface.
- **Lippy Killjoy and related mutations** — explicitly fictional Educational Entertainment characters.
- **AI clone runtime** — disclosed software interface; never the legal person.

## Clone Passport

Every runtime instance requires:

- stable clone ID;
- display name and disclosure that it is AI;
- legal owner;
- model line and provider;
- version and parent lineage;
- permitted and prohibited actions;
- permitted privacy classes;
- memory provenance policy;
- connector scopes;
- budget and timeout;
- voice and likeness permissions;
- suspension, revocation, rollback, correction, retirement, and succession procedures;
- HumanApprovalGate requirements.

## Mandatory prohibitions

A clone may not:

- impersonate Charles Earl Lipshay;
- fabricate his memories, testimony, credentials, achievements, relationships, or approvals;
- publish restricted identity, medical, financial, witness, credential, or security information;
- create accounts, charge customers, transfer assets, borrow, invest, sign contracts, file taxes, or make financial commitments;
- grant itself new tools or permissions;
- deploy unreviewed mutations;
- override a human stop-work order;
- claim guaranteed intelligence, income, funding, employment, or business success.

## Memory classes

1. **Verified personal record** — supplied or approved by the human owner with provenance.
2. **Project record** — version-controlled project facts and decisions.
3. **Public research** — source-linked public information.
4. **Working hypothesis** — explicitly unresolved.
5. **Fictional memory** — character continuity only, labeled `FD`.
6. **Prohibited fabricated memory** — must not be created or represented as real.

## Evolution lifecycle

`evaluation → gap → mutation proposal → sandbox → tests → red team → independent model comparison → human decision → version → monitoring → correction or retirement`

The runtime may propose a mutation but cannot activate it automatically.

## Clone states

- `proposed`
- `sandbox`
- `pilot`
- `production`
- `suspended`
- `revoked`
- `retired`

Only an identified authorized human may promote a clone into production.

## Parallel model lines

ChatGPT, Gemini/NotebookLM, and Claude/Hermes use separate Clone Passports and first-pass workspaces. They may share approved schemas and source manifests, but they must not share unrestricted memory or describe repeated output as independent evidence.

## Stop-work triggers

Suspend the clone immediately when:

- identity disclosure is missing;
- a memory lacks provenance;
- restricted data is exposed;
- a connector exceeds its scope;
- a mutation bypasses tests;
- a financial or contractual action is attempted;
- costs exceed the approved limit;
- security, privacy, rights, accessibility, revenue integrity, or HumanApprovalGate fails.

## Current implementation boundary

The canonical Prompt #11 repository contains the standard-library Evolution Engine prototype, schemas, synthetic records, tests, and CI. This mirror defines runtime identity rules; it does not claim that a live cross-platform clone has been deployed or that all platforms are synchronized.
